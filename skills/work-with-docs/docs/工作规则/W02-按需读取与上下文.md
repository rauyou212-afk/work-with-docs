# W02 · 按需读取与上下文

[文档目录](../00目录.md) · [上一词条](W01-文档组织与链接.md) · [下一词条](W03-文档审阅.md)

## 按本次理解需要读取

先遵守适用的 AGENTS 及其要求的接续规则，再沿“入口 → 指定词条 → 必要关联”读取。理解不足时补读相关概要和目录，明确本次工作目的、权威正文和适用要求；不假定新会话天然掌握项目。无需为“首次使用”另建登记文件或额外流程。

链接是发现资料的线索，不是递归读取命令。目录已能定位时不遍历全部分目录；术语按需要进入本库唯一术语入口，再读对应定义。普通当前工作不默认读取历史讨论、旧原稿或全部记录；追溯请求、基线比对、查证依据时再读取相关片段。

同一会话已读、未变且仍可用的内容直接复用，不因新一轮回答再次读取。编辑前只核对本次目标及必要关联的最新内容；文件可能被其他人修改、上下文丢失或来源冲突时，补读受影响范围，不默认重读全库。保留用户或其他会话的新修改，不凭过期摘要覆盖正文。

用户要求全文阅读或整体审查时执行指定范围，资料较多则分批完成并说明覆盖范围，不以按需读取为由省略用户要求。

## 控制重复读写

- 优先局部编辑，不为几处改动重新生成整篇正文；结构调整确实需要重组时再扩大范围。
- 核验覆盖实际受影响内容与链接，不把局部改动自动升级为全库审查。工具只返回所需片段或检查摘要，不将整库、整份差异和无关日志重复载入。
- 落文后在聊天说明具体改了什么、结果是什么，并给文件入口，不重复粘贴全文。用户需要理解原因或用法时展开解释；只说明影响本次判断的具体限制，不固定复述背景、流程位置或已确认结论。
- 只加载本次所需规则和模板，不同时通读本技能、项目管理技能和全部历史；链接检查可批量运行，不要求逐个读取所有被链接的正文。

文件数量不等于载入上下文数量。拆分会增加标题与导航，全部加载时可能比单文件更长；节省来自减少无关读取和重复生成，不承诺固定 token 节省或缓存命中率，也不把磁盘文件变化等同于缓存失效。

这里控制的是无关读取和重复工作，不是正文的信息量。写作按 [W08](W08-写作与表达.md) 优先保证理解，不能为减少上下文而省去读者需要的解释、关系和例子。

## 接续

接续时从总目录定位权威正文，按需要读取 `待讨论.md` 和相关工作材料。历史归档、旧原稿及已有结果记录仅在需要追溯时读取，不把完整讨论历史当作常规入口。现有资料足以继续工作时直接复用，不再生成一套状态文件或过程摘要；确需额外交接时，按用户或项目的明确要求提供最少必要信息。

理解不足时补查原文；保留理解结论所需的来源和依据。工作材料与待讨论清单的维护见 [W04](W04-会议与阶段总结.md)，正式正文和按需记录见 [W05](W05-正式落文与记录.md)。
