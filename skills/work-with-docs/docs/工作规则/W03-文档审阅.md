# W03 · 文档审阅

## 接收与处理

从用户任务和适用规则确定审阅范围、权威正文、交回原稿、需比对的发出基线及当前接续。本地已有资料自行定位；缺失的依据注明缺口，不把猜测写成用户改动。原稿保留按 [W05](W05-正式落文与记录.md)。

区分用户直接改写、明确决定、建议、疑问和待核实事实。保留原始批注证据，助手标记与用户标记区分并沿用项目符号；已处理批注是否从当前稿移除按现有审阅约定执行。未改的部分不自动视为同意，已定规则不重复询问。

用户明确授权处理批注或修订时执行该范围，不因工作方式叫“审阅”再设审批。只请求对仍影响任务的实质歧义作决定；`grill` 和 `gloss` 均按需开启，普通审阅不自动变为全面访谈。

事实依据不足时查明具体缺口，本轮能解决的事项直接处理；需要留待后续的事项先在聊天说明，经用户授权后按 W04 写入待讨论，已有任务则引用其位置。有继续使用价值的审阅材料按 W04 保存。必要关联在授权范围内一并处理，超出范围先说明拟影响的位置。即时修订按 W05 选择值得长期保存的确认结果，批注往返和处理过程不进入正文。

按 [W08](W08-写作与表达.md) 检查表达：读者是否需要猜测术语、范围或操作，是否只有抽象结论和链接，是否反复添加不影响判断的限定。优先补清含义与关系，再删重复和空话；评价篇幅时不能以越短越好为标准。

## 核验与交付

文档审阅和会议讨论采用同一确认与落文标准。正文、必要目录、引用及恢复原稿按 W05 处理；清单维护按 W04，在授权范围内移除已完成条目或更新剩余工作。

聊天交付具体结果、修改入口与影响判断的必要限制；文稿审阅通过不代表现实工作已完成。用户或项目要求结果记录时按 W05 维护，确需额外交接时参考[审阅交接提示](../模板/审阅交接.md)。
