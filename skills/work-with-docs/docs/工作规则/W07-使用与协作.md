## 使用示例

| 想完成的工作 | 可以直接这样说 |
| --- | --- |
| 普通整理 | “使用 work-with-docs，把这批已确认结果整理为分层目录与独立主题文档。” |
| 文档审阅 | “审阅这几个词条，按我已确认的批注修订。” |
| 改善表达 | “这段太抽象，请写清做什么、大概怎么做、结果写在哪里，并补一个有助理解的例子。” |
| 概览摘要 | “为这个父主题概览补写简洁的首段摘要，概括已有结论、影响和行动，并将关键短语链接到对应正文。” |
| 主持会议 | “本次开会讨论 1.1—1.4，由我逐项提出议题。” |
| 深入追问 | “grill 1.2 的边界。” |
| 术语梳理 | “gloss 这里的‘申请’与‘登记’。” |
| 组合方法 | “先 gloss 这些概念，再 grill 有分歧的规则。” |
| 收束 | “停止追问，汇总本轮结论。” |
| 正式落文 | “以上确认，按讨论结果更新这些词条及必要关联。” |
| 阶段结果即时落文 | “这一项已经确认，现在更新对应正文，其余继续讨论。” |
| 待讨论与待办 | “把这个问题和剩余待办加入本库的待讨论清单。” |
| 工作材料 | “保存这份仍需比较的方案，方便下次继续讨论。” |
| 阶段归档 | “归档这次研究，整理现行结论、剩余待办和目录编号。” |
| 版本定档 | “归档这个阶段，并将现行正文定档为 V1.0。” |

这些是自然语言操作指令，无需固定口令。默认普通文档工作；提到单词或引用示例不等于开启该能力。`grill`、`gloss` 不自行授予写入权限。讨论、工作材料与待讨论清单见 [W04](W04-会议与阶段总结.md)，正式写入与按需记录见 [W05](W05-正式落文与记录.md)，归档与定档见 [W06](W06-旧文档迁移.md)。

## 阅读与安装

本技能为 UTF-8 文本，不包含可执行脚本，不要求安装 Python、Node.js、Git 或 Obsidian。可以使用支持 Markdown 的阅读器；如使用 Obsidian，将本技能的 `docs` 目录作为 Obsidian 仓库打开，或完整放入已有仓库，从 [00目录](../00目录.md) 点击独立词条。说明导航留在此目录内，个人 Obsidian 配置不属于安装包。

从其他文档库引用本技能时，按 [W01](W01-文档组织与链接.md#库内与库外链接)生成库外链接；技能已安装不等于其目录已登记为 Obsidian 仓库。

在支持本地技能的环境中，将完整 `work-with-docs` 文件夹放入技能目录，文件夹内直接包含 `SKILL.md`。保留内部路径与 UTF-8 编码。Windows 下使用当前运行 Agent 所在环境的技能目录，原生 Windows 与 WSL 的用户目录分别处理；文件操作采用当前环境支持的工具，不假定 Bash 或 macOS 命令可用。其他环境依其实际加载方法，不因文件存在就声称客户端已成功加载。

## 其他技能与项目规则

本技能自包含原 Grilling 的依赖追问、domain-modeling 的概念澄清及 Grill with docs 的文书衔接中所需的方法，不依赖另装或自动调用这三个技能。原技能保持原状；在没有采用本方法的其他文档库中，仍按其各自约定工作。

本技能采用唯一术语入口加词条权威定义的方式，入口可与术语父文档合并；原版 domain-modeling 可能要求 GLOSSARY 保存全文，两者不能同时维护竞争正文。调用者必须沿用本次文档库已明确的权威和写入约定，不能仅因更换技能而覆盖结构；新冲突先核对适用约定，再处理受影响范围。

`personal-project-management` 负责项目身份、工作包、进度、实施授权、测试验收及本地 Git；本技能负责文书讨论、写入和组织规则。调用时传入本次范围、当前身份与可写位置、权威入口、必要基线、已确认内容、落实标准和已有授权；返回简短结果、实际入口及必要未完成事项。已有任务系统保持其权威；用户授权写入待讨论时只放必要入口，收录条件见 W04。上游的专业记录要求在其指定材料中执行，不转为所有文书任务的固定产物。

只读取本次需要的入口和方法，不把两套手册全部载入。按 AGENTS 判断工作类型并遵守其约束，不由本技能另定专业记录格式或技术执行要求；没有 AGENTS 时沿用用户任务与既有约定。

技能不能扩大身份或环境权限，不能凭文稿完成宣称现实工作已落实。专业资料具备权限与证据时可核对，缺口如实说明；自动开发、发送跨聊天消息等不由文书授权推导。
