# W01 · 文档组织与链接

[文档目录](../00目录.md) · [下一词条](W02-按需读取与上下文.md)

## 层级目录与独立主题

新建、供人持续阅读和维护的正文采用**层级目录式文档**：可点击的分层总目录，加上独立主题文档。“词条”指一份独立 Markdown 文档，不是必须创建的 `词条/` 文件夹。文件夹按领域、模块或父主题命名，目录用嵌套列表表达逻辑层级，不把所有子主题挤进表格的一格或长文的页内锚点。

每个进入正式目录的主题节点对应一个独立文件，包括父主题与子主题。能够单独查找、引用、审阅和维护的子主题应拆开，即使篇幅较短；例如 F01.1、F01.2、F01.3 各自有不同职责时，就分别成文。长篇幅是检查拆分的提示，不设固定字数或行数门槛。普通步骤、例子、字段和同一主题内的局部小标题不自动拆文件或建目录。

有独立子词条的父主题建立文件夹：父词条放在其中的 `00概览.md`，正文标题保留完整编号和名称；叶子词条文件名用“编号＋名称”。子主题继续拆分时采用同样结构。父文档以 [W08 的首段摘要与有效索引](W08-写作与表达.md#概览首段摘要与有效索引) 开篇，随后[建立当前层的整体认识](W08-写作与表达.md#建立当前层的整体认识)，再提供详细内容与子目录。上一级帮助读者理解背景和子主题之间的关系；子页据此展开当前主题，需要时再说明内部组成。具体形式随内容选择，阅读层次不等于必须设置固定栏目。长度、适用范围与表达要求统一见 W08，不在模板或各级目录重复维护。

```text
00目录.md
流程/
├── F01-项目探索与定位/
│   ├── 00概览.md
│   ├── F01.1-理解问题与使用场景.md
│   ├── F01.2-查明事实与关键风险.md
│   └── F01.3-收敛目标与探索路径.md
└── F02-产品需求与交互/
    ├── 00概览.md
    └── F02.1-明确概念、关系与范围.md
```

这套结构适用于说明书、研究结果、长期方案、流程、计划和术语等正式正文。待讨论清单经用户授权按需维护，每库一份；工作材料按主题和后续用途组织，见 W04；按需结果记录见 W05。辅助材料不套用正式主题的拆分和编号要求。`AGENTS.md`、`GLOSSARY.md` 等约定入口以及代码、配置、证据和附件保留所需格式。用户指定其他交付格式时遵从；汇编或导出不成为第二套可编辑正文。

优先沿用已有入口和稳定 ID；已有文档只在获准调整结构时迁移，不因局部编辑强制重建。无实际内容不预建空文件树；用户只要大纲时，在目录列提纲即可，不把待讨论提纲冒充正式主题正文。

## 编号与内容归属

主题编号的前缀只使用一个大写英文字母，禁止使用容易与数字1混淆的 `I`；后接数字表示主题与层级，例如 `F01`、`F01.2`。不同用途的父文档可各用一组编号，选取尚未占用的字母，避免与本库的问题编号混淆。`00目录.md`、`00概览.md`、日期记录和约定入口保留各自命名；既有验收、协议等业务标识不属于文档主题编号，不随目录整理改写。

功能、共用规则、质量要求、术语和界面设计等职责不同的内容，在需要独立查阅时分别建立父文档，通过链接引用共同内容。多个产品或客户端共用资料时，明确各自适用范围；目录放在一起不代表规则和操作完全相同。

日常修改与普通迁移沿用已有编号；用户发起归档后，默认在本次整理范围内重新连续编号，同步文件名、标题、目录与受影响的当前引用，历史归档保持原样。其他重排按用户指定范围执行，入口清理见 [W06](W06-旧文档迁移.md)。局部改文不自动触发全库改号。

## 唯一正文与导航

- 一个事实或规则只有一个权威位置；关联词条可概括本处需要的含义并链接详情，不能只给链接让读者自行拼出意思。概括须与权威正文一致，规则变化时同步相关表述，不维护第二套完整规则。原稿和发出稿属于明确标识的历史快照。
- 总目录用嵌套链接列主题编号和标题，父节点链接其 `00概览.md`，子节点链接对应文件。链接后按需要补充用途说明；目录用于查找内容，不默认维护文档完成状态，核验见 [W05](W05-正式落文与记录.md)。
- 每个词条有返回总目录链接，子词条还有上一级链接，父文档有子目录。关联词条和外部来源按需要引用，具体写法按下节选择，锚点只补充定位。
- 移动或改名时定位并更新入链；编号按上节约定处理。不为局部改字通读所有正文；检查本次实际影响的链接。
- 模板用于选取所需内容，生成时替换真实导航，删除无用途字段和模板说明。见[目录模板](../模板/目录页.md)、[词条模板](../模板/独立词条.md)和[父主题概览](../模板/父主题概览.md)。

## 库内与库外链接

先按读者使用的阅读器判断链接边界。Obsidian 以实际打开的 vault 为库；同属一个 Git 项目、磁盘父目录或工作区，不代表位于同一 vault。聊天中的可点击路径语法也不等于 Markdown 文件中的可用链接。

| 目标位置 | Markdown 文档中的写法 |
| --- | --- |
| 同一文档库；在 Obsidian 中为同一 vault | 使用相对文件链接，如 `[词条](../主题/词条.md)`。 |
| 另一个已登记的 Obsidian vault，且已知读者使用 Obsidian | 使用 `obsidian://open?vault=库名或ID&file=相对该库根目录的文件路径`，各参数值分别做 URI 编码；以实际登记信息为准。 |
| 其他本地文件或目录 | 使用 `file:///` 文件 URI，交给系统默认应用打开；不要为建立链接自动注册仓库或更改默认应用。 |
| 网页 | 使用来源的完整 `https://` 地址。 |

裸写 `/Users/...`、`C:\Users\...` 等系统绝对路径，或用 `../` 跨出 vault，不能让 Obsidian 打开库外文件；前者会被当成库内路径。尖括号只能包裹路径，不能改变它的打开方式。库外目标应按上表带协议，库内路径则保持相对引用。

Windows 文件 URI 使用正斜杠并保留盘符，例如 `file:///C:/Docs/guide.md`；Markdown 库内链接也使用正斜杠。共享到其他设备时优先保留库内相对链接，本机绝对路径不能作为接收者的通用入口。

URI 从真实路径生成，正确编码空格、中文和 `#`、`&` 等特殊字符，避免重复编码。Obsidian 章节定位使用真实标题或块 ID，将 `文件路径#标题` 整体编码到 `file` 参数中；不要直接照搬其他阅读器的标题 slug 或 HTML 锚点。

`file:///` 只保证交给默认应用打开文件，不默认承诺章节或行号跳转。需要定位时在链接文字或旁边保留章节名称、行号；聊天专用的 `文件.md:42` 不写进文件 URI。目标不存在时先核对迁移记录，无法确定则说明缺口，不猜同名文件或创建空文件。批量修复只处理授权的现行引用，历史原稿和冻结归档保持原样。

这些写法面向本地文档阅读；共享或发布时按接收者环境调整，聊天交付链接遵从聊天客户端约定。格式依据见 [Obsidian URI](https://obsidian.md/help/uri) 与[库外文件链接](https://obsidian.md/help/drag-and-drop)。

## gloss：术语梳理

用户以操作指令开启 `gloss` 时，只梳理当前指定的概念及必要关联：

1. 查找现有定义和用法，识别同名不同义、多名同义、含混边界及关系冲突。不能仅因标题存在就把所有章节都当术语。
2. 用具体场景厘清概念：它指什么、不包含什么、与相邻概念如何区分。术语可以是业务对象、流程、状态、具备特定含义的页面或视图名称，例如“调研地图”“规划地图”，不限于数据实体。
3. 提出标准名称、易懂的定义、确有必要的别名或易混称呼以及关联词条。先用熟悉的语言说明它指什么；含义仍不清楚时补一个贴切例子，不以一两句话为目标。具体操作和详细规则留在相应正文，不扩成百科或实现说明。
4. 可查证事实从适用资料核实，表达业务取舍的歧义由用户确定。已经确认的名称和含义不反复询问；新定义未确认前保留为建议，不覆盖权威定义。

`gloss` 不自动开启 `grill`；需要深入追问时依用户指令结合 W04。普通写作仍应修正明显误用，但不自动开展全库术语盘点。

## 术语入口与定义位置

文档库只维护一个术语查找入口。已经有“术语”父文档时，优先由其 `00概览.md` 合并承担分类目录、名称和别名索引，不再另建内容重复的 `GLOSSARY.md` 或 `术语索引.md`。没有术语父主题、只需一个轻量索引时，可沿用其中一种文件名；`GLOSSARY.md` 不是必须存在的固定文件。

索引列名称及指向唯一权威定义的链接，可保留帮助查找的短说明。定义写在独立术语词条的定义段，或复用其他主题中已有的定义。例如已有“活动本体”词条，就链接该词条，不另造同名定义。紧密相关的概念可在同一主题中分别定位；详细操作和业务规则仍留在对应功能正文。

合并已有“术语”与 GLOSSARY 时，保留名称、别名、旧称查找和有效定义入口，更新全部当前引用，删除重复的索引或过期跳转文件。原稿按 W06 保留，不通过复制定义全文或同步两套正文实现合并。没有迁移授权时沿用既有入口，不因调用 gloss 自动改名或重组。

术语草案先在聊天讨论，需要继续比较或接续的材料按 W04 保存；未决概念需要留待后续且用户授权收录时，才进入待讨论清单。经确认并授权落文后，同步定义、唯一索引及必要引用。无需调用原版 domain-modeling，也不改变原版技能在其他场景的规则。
