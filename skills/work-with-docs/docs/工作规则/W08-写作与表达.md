# W08 · 写作与表达

[文档目录](../00目录.md) · [上一词条](W07-使用与协作.md)

本文规定文档怎样先帮助读者判断是否值得继续阅读，再建立整体认识，最后按需深入细节。摘要与整体说明各有作用，表达形式按内容选择；新写、改写、审阅及维护概览时采用这些规则。

## 按文档类型安排开头与正文

以下分类与报告开头规则优先用于新生成的文档。既有文件无必要不回头大改；用户指定修订，或确有影响理解、事实准确性的具体问题时，只调整所需内容，不因采用新规则全面重写旧稿。

先按文档的主要用途选择写法。分析型帮助判断问题与取舍，报告型交代一次行动得到了什么，描述型帮助理解对象、规则或流程。类型用于组织内容，不要求增加类型标签或套用固定栏目；混合文档按主要用途开篇，相关章节再采用合适写法。

| 文档类型 | 开头先让读者知道 | 后文展开什么 |
| --- | --- | --- |
| 分析型 | 要判断的问题、当前判断及关键依据；尚无结论时说清未决点。 | 事实与假设、原因、方案比较、取舍及不确定性。 |
| 报告型 | 这次行动的结论、结果意味着什么或有何启示，以及仍需注意的问题。 | 行动范围、方法、结果明细和证据；执行顺序仅在有助理解时保留。 |
| 描述型 | 对象是什么、有什么作用，主要组成怎样关联。 | 定义、结构、规则、使用方法及必要例子。 |

**执行结果报告先交代结论与意义，再进入执行明细。** 读者只看开头，就应知道这次行动证实或否定了什么、得到的成果可以怎样使用，以及哪些未完成事项或证据限制仍会影响判断。启示须由结果支持；只完成局部工作时如实说明局部结论，不强行提炼普遍经验。重要问题放在开头，详细依据在后文解释。

下文的三层阅读顺序适用于不同类型；短报告可用一个自然段完成开头，不为补齐栏目重复内容。描述型没有行动结论时，直接说明核心认识及用途。

## 先建立整体认识，再展开细节

读者可以先用摘要判断主题是否与当前需要相关；决定继续后，再了解它由哪些主要部分组成、各自大概有什么作用、怎样关联。获得这种基本认识后，读者可以暂时停下，也可以选择一部分深入。写作者据此安排信息，让后面的定义、步骤和例外都有位置可放。

| 阅读层次 | 帮助读者做什么 | 内容重点 |
| --- | --- | --- |
| Summary | 判断是否继续阅读 | 核心结论、重要影响与条件、已确认行动及关键入口。 |
| 整体认识 | 形成可独立使用的初步理解 | 当前主题、主要组成的大概含义或作用，以及相互关系。 |
| 详细内容 | 按需理解、操作或核查 | 具体定义、原理、步骤、规则、例外、证据和详细图示。 |

这是信息展开的顺序，成品的标题和表现形式按主题选择，不强制套用三个固定栏目。

## 写作优先级

按以下顺序取舍；压缩篇幅不能牺牲理解、结构或内容完整性：

1. **易读、易懂。** 使用熟悉、具体的语言，专业术语首次出现时解释。读者应理解“是什么、为什么”；操作或流程还需说明“做什么、大概怎么做、得到什么”。
2. **层级目录式文档。** 用可点击的分层总目录和独立主题组织资料；父页说明整体与子主题关系，子页承载具体内容，拆分后仍能连续理解。结构按 [W01](W01-文档组织与链接.md)。
3. **全面、准确，适度说明条件。** 覆盖当前用途需要的信息，保留影响判断的真实条件、事实依据和不确定性，减少泛化免责声明与假设性风险。
4. **避免冗长。** 删除重复、空话、无关背景和过程流水账；保留有助理解的解释与例子。详细正文按用途决定篇幅；摘要与整体说明按下文控制长度，不把需要的解释压成结论提纲。

这些优先级也适用于摘要、问题清单和聊天说明，详略由用途决定：摘要帮助判断是否继续，整体说明帮助建立全貌，详细解释供按需深入。

## 概览首段摘要与有效索引

父主题的 `00概览.md` 在顶部导航后的第一段正文写 summary，不另设“摘要”或“summary”标题。含有多个关联部分、需要分层理解的叶子文档也采用这种开头；简单主题一句定位即可，普通小节、总目录和辅助材料按用途处理。

Summary 通常为 **50—100 个中文字**，帮助读者判断内容是否与当前需要相关、是否值得继续阅读。它与后面的整体说明分别承担任务、分别计数。

**先给结论，再交代影响与已确认的行动，保持简洁清晰。** 只概括当前权威正文已有的有效内容，保留会改变判断的关键条件；理由、论证、例子和详细步骤留在后文。术语或知识说明没有决策时，概括核心认识及使用意义；有已确认行动才写行动，无行动时自然省略。

**将关键短语直接链接到对应正文，构成有效索引。** 链接到能支撑该结论、解释该影响或执行该行动的子文档，必要时定位到具体章节；按 [W01](W01-文档组织与链接.md#库内与库外链接)选择真实可用的库内或库外链接，链接文字说明目标内容。只选理解与行动所需的入口，完整子目录仍在后面。摘要本身应能独立理解，链接用于深入查阅。

新建父主题概览时默认生成。旧文档在获准修订对应主题时补充；当正文的结论、影响、行动或相关链接变化时，同步维护受影响概览。关联更新仍遵守本次写入范围，无权更新的关联位置在交付时说明；全库回填由用户另行指定。

完成时核对：读者只看首段即可抓住核心认识、判断是否继续并找到关键正文；每项概括与当前正文一致，链接目标有效。摘要与整体说明各自增加所需信息，详细论证和步骤留在第三层。示例见[父主题概览模板](../模板/父主题概览.md)。

## 建立当前层的整体认识

进入详细正题前，先交代当前主题是什么、有哪些主要部分、它们大概是什么或有什么作用，以及怎样关联。关系可以是整体与局部、先后、依赖、协作或因果，按内容选择；仅列章节名称还不足以形成整体认识。读者只看到这里，也应能用自己的话描述基本全貌，暂时不读细节。

父主题概览默认承担这项工作；复杂叶子文档按需要说明本篇内部的关系，简单主题用一句定位，普通小节不逐层重复。上一级提供相关背景，本篇交代当前层的内容与位置。某个组成若用一两句话仍无法说清含义或作用，保留它在整体中的位置并引导到正文了解，不强行压成容易误解的口号或定义。

整体说明的解释文字通常 **100—150 个中文字，最多 200 字**；同一页这一层的解释文字合计，摘要另计。计读者可见的文字，链接地址与 Markdown 标记不计。短主题可以更短；复杂内容通过分层和链接展开，保持开头的长度边界。

根据内容选择短段落、简短列表、简表、简单示意或贴切例子。采用简表时通常列 **3—5 个主要项，每项一句短说明**，交代组成、作用或关系，与段落互补。表格不是必填项，也不承载整套细则；完整步骤表、复杂流程图、推导和例外放到后续详细内容。用自然的主题标题衔接即可，不要求出现“整体认识”等固定栏目名。

例如，流程说明先交代阶段与循环怎样配合，再列完整步骤；概念说明先介绍主要对象及关系，再展开定义与边界。选择能帮助当前读者理解的形式，不把某个示例推广为所有文档必须采用的版式。

## 把内容说具体

根据文档用途和读者已有知识确定解释深度。供学习的材料应交代概念和理由；供操作的材料应说明如何开展、得到什么；供查阅的材料应便于定位具体规则。用户已说明用途时直接采用，不为写作额外发起问卷。

先说清当前主题讲什么、解决什么问题，再展开内容。使用具体的对象和动作，避免只写“收敛范围”“明确边界”“完成闭环”等抽象概括。专业词语有必要时保留，并在首次出现处用日常语言解释；同一词语保持同一含义。

说明流程或操作时，按实际需要交代：从什么情况开始、依据哪些资料、要做哪些事、大致怎么做、形成什么结果，以及如何判断已经完成。涉及模板或其他文档时，点明对应的内容和写入位置。它们是检查思路，不是每篇必须填满的固定栏目；普通概念说明无需套用操作步骤。

例如，“写清行为与业务验收”只能概括主题，正文还需说明：

> 先按实际使用顺序写出用户从哪里进入、执行什么操作、系统如何回应，再补充取消、失败等相关情境。以便签编辑为例，若已确认“取消后保留原内容”，验收条件可写为：“已有内容 A，修改为 B 后取消，再次打开仍显示 A。”正常操作写入 T03.3，取消规则写入 T03.4，验收条件写入 T03.6。

这里的便签和编号仅为写法示例，使用时替换为当前文档的真实内容。例子用于解释已有规则，不借例子新增未经确认的要求；一个贴切例子能说明时，不堆叠多个近似例子。

## 拆分后仍能连续阅读

父页在首段摘要之后建立当前主题的整体认识，再给出细节与子主题入口；子页接续上一级背景，按本篇复杂度交代用途和内部关系。标题尽量直接指明对象或工作，例如“写出用户操作与预期结果”。需要时解释章节之间的关系，避免通篇只剩并列清单。

链接负责定位和深入查阅。当前段落应有足够说明，让读者知道链接内容与本段的关系；不能只给编号、术语或“详见某处”，要求读者跳转后自行拼出意思。引用其他规则时，可以概括本处用到的含义并链接权威正文，按 W01 保持一致，不另立一套规则。

段落用于解释因果和含义，列表用于步骤或并列事项，表格用于对应和比较。按阅读需要选择形式，不为了短而把所有解释挤进表格，也不为了完整把能独立理解的主题堆成一篇长文。

## 全面准确，适度说明条件与风险

内容全面，是覆盖当前用途所需的概念、关系、步骤、条件和结果，不是穷举所有可能情况。准确表达已知事实；必要时说明已知的证据缺口及其对使用结果的影响。尚未核实的判断和临时方案按 W04 保存，正文准入按 W05，不能用模糊措辞把猜测包装成事实。

影响读者决定或行动的前提、限制和风险，应在相关位置清楚说明。同一条件在适用的共同位置说明后，后文按需引用；不在每段重复“仅供参考”“不保证”“仍需核实”，也不为假设性的例外不断追加否定句。需要限定时，直接说明条件和结果，避免连续使用“可能、原则上、视情况”等词却不交代具体情况。

例如，资料只支持本地保存时，可写“本节说明本地保存；跨设备同步尚未确定”，无需逐段重复不同环境可能存在差异。用户会核查内容并理解风险，因此减少泛化提醒；真实未知、适用条件和重要限制仍应如实交代。

## 写完后按读者需要检查

先分别只读摘要、只读到整体说明，再阅读详细正文：第一层能否让读者判断是否继续；第二层能否让读者说出主题、主要组成的作用及相互关系；第三层能否支持具体理解、操作或核查。检查整体说明的长度及前两层是否互补，不能只检查有没有摘要、表格或链接。

检查读者沿实际上级入口阅读后，是否能理解本篇；流程是否让人知道从哪里开始、做什么、结果在哪里。若仍需猜测指代、术语或省略的关系，补清相应位置；开头放不下的解释引导到正文。

删去重复结论、无关背景、空泛过渡和执行流水账；保留能消除误解的理由、条件与例子。不以字数少、句子少或链接多作为写得好的标准。用户或项目需要结果简记时，按 W05 概括具体结果，详细解释留在正文；简记也不能只剩“已明确范围”等无实际内容的动作标签。
