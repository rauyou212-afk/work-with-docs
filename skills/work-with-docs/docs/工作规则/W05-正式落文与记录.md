# W05 · 正式落文与记录

[文档目录](../00目录.md) · [上一词条](W04-会议与阶段总结.md) · [下一词条](W06-旧文档迁移.md)

## 正式正文保存什么

正文保存**有重复阅读价值或需要长期保存的确定内容**：已确认的规则、准备长期采用的方案、有依据的事实，以及理解和使用它们所需的解释。内容确定不代表必须落文；按文档用途判断它是否值得保存。

已确认、准备长期采用的方案可以进入正文，即使尚未实施或验证。准确表达它是方案、要求还是已实现的事实；不能把“决定这样做”写成“已经做到”。事实结论保留影响理解的来源、范围和条件。研究结论可以入文，尚未核实的判断、研究经过及临时方案按 [W04](W04-会议与阶段总结.md) 留在聊天或工作材料中。

写清结果及必要的理由、条件、关系和例子，详略按 [W08](W08-写作与表达.md) 判断；“只记录结果”不等于只写结论提纲。问答往返、修改经过和 AI 临时执行轮次不进入正式正文。领域本身的正式阶段和仍适用的版本要求照常说明。

## 写入与当前有效内容

先核对已确认结果、写入范围、当前权限和相关最新正文，保留用户或其他会话的新修改。已有明确确认和写入授权就执行；本轮或阶段结果可以即时更新，尚未收敛的答案继续讨论。

当前正文表达当前有效规则或有依据的现状。已确认 B 取代 A 时，直接替换有效正文及必要关联，不在正文保留“A 改成 B”的经过或追加冲突补丁。规范要求 B、实际仍为 A 时，分别准确说明要求与现状；本轮能完成的工作直接处理，后续事项按 W04 经用户授权后登记，已有任务则沿用其入口。

## 按恢复需要保留原稿

- 已有 Git 版本或原稿能准确恢复本次内容时直接复用，不另存副本，也不为此强制建立 Git。
- 普通措辞、排版和小范围补充不另存快照。
- 大段重写、删除或迁移，且没有可用恢复来源时，保留必要原稿，放入 `工作材料/`，后续随阶段整理。项目已有原稿或发出基线位置时优先复用，不复制无变化的整套文书。

本节原稿用于恢复本次修改；用户要求保存阶段版本时，按 W06 定档。项目明确要求的专业记录和保留规则继续适用。

## 核验与交付

核验按当前版本和本次范围判断：文档表述及交付结论是否有相应依据。本技能检查内容、定义、摘要、链接和关联事项；现实工作是否落实，依据用户、AGENTS、项目规范或专业工作提供的证据。文稿完成、实际实施、测试通过和用户验收分别表达。

目录用于查找内容，默认不维护“已有正文／已讨论／已落实”等状态，也不计算“词条完成”。待讨论只管理用户授权收录的后续事项，项目自己的实施、测试和验收记录仍按其要求维护。内容发生变化时检查受影响的判断，不沿用已失配的证据。

完成前检查本批改动符合确认结果与授权，受影响正文和概览一致、链接有效，获准维护的已解决事项及其当前引用已清理。尚未完成的工作在聊天说明，已登记的引用现有入口，不为交付自动补建条目。表达与概览检查按 W08；必要的原稿和项目记录按适用要求处理。

链接按 [W01 的库内外规则](W01-文档组织与链接.md#库内与库外链接)核验：相对路径留在实际文档库内，外部 URI 解码后对应真实文件、已登记仓库及必要标题。修复跳转故障时，在目标阅读器抽查受影响的打开方式；文件存在、链接被正确识别和实际打开目标分别确认，不能仅凭路径存在宣称点击验证通过。无法操作阅读器时说明尚未实测的范围。

复用仍适用于最终内容的检查结果；有新变化、失败或未解决问题时补查相关部分。结果达到要求、必要核验完成后结束，不为形式完整追加检查、报告或证明文件。

聊天说明具体结果、实际入口和影响使用的必要限制，不复述全文。需要执行结果报告时，按 [W08 的报告型写法](W08-写作与表达.md#按文档类型安排开头与正文)先交代结论、意义和重要问题，再展开明细。需要额外交接时使用[审阅交接提示](../模板/审阅交接.md)。

## 按需结果记录

结果记录按需维护，不默认生成每日简记。只有用户明确需要回顾记录，或项目已有记录要求时才创建或维护，沿用其位置、格式和周期；没有位置约定时可放在 `工作材料/`，按用途命名并复用同用途文件。

记录概括具体决定、影响含义的必要条件及有意义的内容变化，链接详细正文。让未参加讨论的读者看懂结果，再删去重复；不以最少字数为目标，也不复制正文、待办清单或执行流水账。已登记的未完成事项只引用唯一位置，其余在聊天说明；清单写入、研究过程和未确认内容按 W04 处理。见[按需结果简记模板](../模板/会议接续.md)。

已有旧记录在用户指定的整理或归档范围内处理；新规则本身不触发全库清理。
