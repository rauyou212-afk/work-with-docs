# work with docs

让读者容易找到资料，理解内容并知道如何使用。适用于说明书、研究结果、活动方案、流程制度和软件开发文件等持续维护的文书。

正式正文保存有重复阅读价值或需要长期保存的确定内容，以及理解、使用所需的解释。已确认、准备长期采用的方案可以入文，实施与验证状态如实表达。临时材料按用途保存在 `工作材料/`，经用户授权留待后续的未决问题与待办由 `待讨论.md` 提供入口。

写作依次优先保证易读易懂、层级结构、全面准确且不过度防御、避免冗长。新增文件、记录或检查应有具体用途；复用仍有效的资料，完成当前任务所需工作后结束。

## 工作流程

1. **确定本次任务。** 读取适用的 `AGENTS.md` 及其要求的规范，明确用途、范围、权威资料、角色权限、交付要求和已有授权；只澄清会影响工作的缺口。
2. **按任务读取。** 从下表选择规则，读取目标正文与必要关联。资料足以理解本次工作及其影响后开展工作；用户要求全文阅读时覆盖指定范围。
3. **讨论或写入。** 讨论、工作材料和待讨论清单按 W04，审阅按 W03。确认且获准写入的结果按 W05 更新正文；组织与导航按 W01，迁移、归档和定档按 W06。
4. **核验并交付。** 检查受影响正文、概览、链接和关联事项，在授权范围内清理已解决的待讨论项。聊天说明具体结果、实际入口和必要的未完成事项；仅在用户或项目需要时另写记录。

## 确认与写入边界

- 用户确认本轮或阶段结果并授权写入后，即可处理该范围，无需等整场讨论结束。已有明确确认和授权直接执行；开启本技能或进入讨论不代表未确认内容可以写入正式正文。
- 待讨论清单的写入与维护由用户授权，已有授权明确覆盖的范围直接执行；本轮对话能完成的事项直接处理，不先登记。具体规则见 W04。
- 在已有文书任务与可写范围内，可按 W04 保存有后续用途的工作材料并告知入口。普通咨询不自动创建文档库；用户要求只在聊天讨论时，内容留在聊天。
- 新建正文采用可点击的分层总目录与独立主题。已有文档保持当前权威，局部修改只处理目标及必要关联；用户发起迁移或归档后按 W06 整理指定范围。
- 文稿完成、实际落实和用户验收分别依据对应事实判断，具体核验按 W05。工作类型、专业记录和验收要求沿用用户及项目约定。

## 按需开启的能力

默认做普通文档工作，保留必要的歧义和冲突检查，不自动进入深度访谈或全面术语分析。

| 用户的操作指令 | 行为 | 规则 |
| --- | --- | --- |
| `grill`，如“grill 这一节” | 在指定范围深入追问假设、边界和未决选择 | W04 |
| `gloss`，如“gloss 这些概念” | 梳理标准名称、定义、别名、边界与关系 | W01 |
| “停止追问”“返回普通整理”等 | 结束对应能力，继续当前文档任务 | 保留已确认结论 |

两种能力可组合，也可用自然语言提出同等意图；不是必须安装的斜杠命令。仅引用单词、讨论技能名称或解释命令不触发。触发只改变分析方法，不扩大讨论范围或写入授权。

## 协作边界

- 本技能自包含 `grill`、`gloss` 所需方法，其他技能仍按各自约定工作；调用关系与术语约定见 W07。
- 本技能不自行规定 ADR、开发阶段或验收制度，没有适用要求时不强制创建 Git、配置多个 Agent 或软件角色。额外交接按 W07 的适用条件提供。
- 接收其他技能任务时继承当前身份、范围及可写位置。文书授权只覆盖文书工作，代码开发、项目实装、改写其他技能及跨聊天发送消息须有相应授权。
